# Tap Guard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make one broken piezo channel a nuisance instead of an outage: hysteresis re-arm, stuck-mute, rate quarantine, quiet-recovery unmute, all announced over serial and `/api/diag`.

**Architecture:** All logic lives in `octagon_core.cpp`'s `readPiezos`/new `commitFire`, so `turn_counter` and `eight` inherit it. The web layer only gains a `muted` field.

**Spec:** `docs/superpowers/specs/2026-08-16-tap-guard-design.md` — the mechanisms, constants and rationale live there; this plan is the file-by-file sequence.

**Constraints:** No compiling or flashing — the user drives the bench. Host pytest is allowed. Commit per task.

---

### Task 1: Host model and tests

**Files:** Create `tests/test_tap_guard.py`

- [ ] Port the guard state machine (armed/streak/muted/lastLoud + commitFire + winner selection) into a Python `TapGuard` class driven at 5 ms steps by per-side reading generators.
- [ ] Tests, per the spec's list: clean tap = 1 fire; 900 ms sustained ring = 1 fire; pinned input = 1 fire then muted ≤ 2.1 s and a *different* side fires normally afterward; 60 Hz hum = ≤ 8 fires, muted ≤ ~2.2 s, unmuted 5 s after hum stops; 4-tap gesture at 500 ms never mutes; 8-tap drum-roll at 300 ms mutes then self-heals; same-scan ghost loses to the bigger delta; next-scan ghost is suppressed while the disarmed winner is still hot; accepted fires alone move the global lastTapMs.
- [ ] `pytest tests/test_tap_guard.py -v` → all pass. Commit.

### Task 2: The guard in octagon_core

**Files:** Modify `firmware/libraries/octagon_core/src/octagon_core.cpp`, `octagon_core.h`

- [ ] Constants next to `TAP_DELTA`: `CHATTER_GAP_MS 400`, `CHATTER_STREAK 8`, `STUCK_MUTE_MS 2000`, `UNMUTE_QUIET_MS 5000` (values + rationale in spec).
- [ ] State next to `lastTapPerSide`: `armed[NUM_SIDES]` (init true), `fireStreak[]`, `muted[]`, `lastLoudMs[]`.
- [ ] `commitFire(i, now)` exactly as specced — debounce, disarm, streak, mute-and-swallow, `lastTapMs` only on acceptance.
- [ ] Rewrite `readPiezos` per the spec's scanner-structure section: per-side loop stamps `lastLoudMs`/re-arms/runs the EMA as today, handles unmute and stuck-mute, and collects hot **unmuted** candidates; winner path = disarmed-winner suppression → `commitFire`; opposite-pair bit requires `armed[opp]` + own `commitFire`.
- [ ] Serial prints on mute (side, cause: chatter vs stuck, unmute condition) and unmute.
- [ ] `octagon_core.h`: `bool sideMuted(uint8_t i);` next to `lastTapForSide`. Commit.
